# Full35 implementation acceptance matrix and stage dependencies

Task `NUTRITION-USDA-FULL35-SPEC-001`; revision `1.0-draft`. This matrix specifies future executable assertions. None of the proposed ingestion/database/browser/recovery qualification below is claimed executed by this documentation PR. Existing exact-head repository CI remains the authoritative gate for this PR; it cannot prove code that has not been implemented.

Requirements are defined in the [mapping](nutrition-usda-full35-mapping-spec.md), [reprojection](nutrition-usda-full35-reprojection-spec.md), and [security/history/recovery](nutrition-usda-full35-security-history-recovery-spec.md) documents. Referenced existing test modules are intended extension points, not claims they already test all new behavior. A future test filename is explicitly marked proposed. All tests use synthetic/local state unless a separately approved official-source offline qualification or Production preflight is identified.

## 1. Hard acceptance rules

A requirement passes only with an executed assertion, exact code/schema/source/mapping identity, test command/result, expected/actual comparison and retained sanitized evidence reviewed independently. A test name, unexecuted fixture, aggregate count, prior-commit PASS or self-approval is insufficient. Any unresolved corrective finding blocks its dependent stage. Do not proceed to a later gate while earlier required correction remains incomplete.

For the exact April release, count assertions are necessary but not sufficient. The independent oracle must compare every source selection, value, unit, derivation, semantic, missing mask, public row identity, raw/source-version identity and before/after tuple in both directions. Hashes must be computed over a documented sorted canonical set; use a separately implemented oracle to avoid proving an implementation with itself.

## 3. Required fixture/oracle design

TEST-01: create a small synthetic USDA-shaped fixture covering all 35 classifications, all 33 eligible source IDs, competing alternatives, independent analytical/NC/AS derivations, zero/null/trace and malformed variants. It must fit the strict parser contract. Create a separate application-only all-35-finite vector so the three source-withheld nutrients are still tested in manual/custom/snapshot scaling. Never label their synthetic manual values as imported USDA evidence.

TEST-02: parameterize all 35 manifest codes at 50, 100 and 200 g. With an additional value `0.1234`, expect `0.0617`, `0.1234`, `0.2468`. Use exact rational expected strings before current final normalization; include half-up boundaries and upper-range failures. For the real source profile, all three withheld fields stay null at every quantity. Assert all 35 output keys, not only four primary metrics.

TEST-03: local full-set qualification uses exact independently verified April bytes outside Git, the frozen accepted identity mapping, and a clean isolated synthetic database representing the 353 public identities. Separate synthetic UUID fixtures from Production identity evidence; compare the same identity set within each environment. The offline source oracle independently computes source amounts/semantics and the expected keyed addition set. Store only reproducible manifests/checksums/sanitized differences in Git. Do not import private owner data or use remote Supabase for this gate.

TEST-04: canonical evidence includes exact code/schema/mapping/raw bytes, commands/tool versions, per-case assertions, expected/actual row-level comparisons, before/after identities, transaction failpoint outcomes, receipt hashes and restore results. Snapshot generated evidence before review. Missing tests, skipped cases and unexecuted requirements remain explicitly incomplete.
