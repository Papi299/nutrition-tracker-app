already exist. Their separate permissions are not removed by 47/48. Serialize
operators and prohibit their reference-changing use throughout Milestone A;
confirm no separately admitted job/operation can mutate public head, nutrients,
public archive state or serving metadata. If one is required, stop A and apply
the permanent-B1 prerequisite before that reference-changing release operation.
Do not assume absence of an app caller excludes a separately authorized operator.

Owners can still create/edit/archive their private custom foods through existing
RLS and versioned APIs. Those are pre-existing mutable references, and retained
legacy actions/direct owner APIs can still represent stale automatic numbers as
manual values. The phased schema installation does not repair that exposure.
New atomic/reference paths check freshness; existing manual/history semantics
remain. The owner decision must acknowledge this continuing risk. For a stable
capture include private custom-reference/owner mutations in the enforceable
cutoff; do not replace it with owner inactivity or an announcement.

Historical diary, Saved Meal/Recipe captures and completed receipts remain frozen
under their accepted semantics. A legitimate historical copy must not be
silently recalculated from changed current references. Null and explicit zero
remain distinct. No existing security or encrypted recovery safeguard is relaxed.

fresh CP1-E/complete before-image, custody, actual v2 registry, independent actors,
