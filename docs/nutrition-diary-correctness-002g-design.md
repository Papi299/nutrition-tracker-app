# 002G bounded design (before implementation)

Development-only independent entry points; no existing backup producer, schedule, recipient, retention, migration SQL, application code or manifest changes.

1. Freeze the complete reviewed migration inventory (44/45), with historical commit/tree and SQL hashes. Replay only repository bytes after explicit boundary selection. Independently bootstrap PostgreSQL 17.6 and Auth 2.196.0 from reviewed immutable images.
2. Use one repeatable-read transaction and exported snapshot for every application value, identity projection and schema reader. Hold local catalog SHARE locks and existing relation ACCESS SHARE locks for the complete acquisition interval. This deliberately requires local administrative control; it is not a hosted-compatible privilege claim. Reject sequences and unknown relations. Prove equal-count concurrent updates preserve the captured point and lost exporter/reader failures abort publication.
3. Inventory all public/ingestion base tables (expected 20 + 41); preserve complete rows as PostgreSQL-produced JSON text strings, never parse numeric values in JavaScript. Compare full sorted values. Compare schema/security dumps including private helpers to independent trusted replay. Never execute source DDL.
4. Seal a single versioned payload using existing CMS AuthEnvelopedData AES-256-GCM/RSA design and a source/recipient/boundary-bound manifest. Decrypt and validate all members before any restore. No production artifact compatibility or automatic producer cutover claim.
5. Reconstruct supported email/password identities with the original UUID through Auth admin createUser. No raw Auth row transfer. Require an independently authorized operator approval bound to the exact artifact identity witness and a separately controlled recovery channel. Fresh target recovery establishes the password. Reject enabled MFA/passkeys/OAuth/SSO/phone/anonymous/unknown durable features; never discard them. Local fixtures qualify the no-factor profile only. Preserve application activation/closure records exactly.
6. Test real old numeric OTP, hash, invitation, refresh and JWT refusal before target credentials are established; real fresh recovery single use, sign-in, lifecycle and RLS. The target stays inaccessible outside its internal task-owned network.

Dependencies: Node 22; repository lockfile unchanged; Docker local Unix socket; pinned PostgreSQL/Auth/PostgREST/Node images; OpenSSL CMS. Selective same-repository reuse: PR206 resource-isolation adapter, PR207 receive-only synthetic mail sink (no application proof HMAC integration), PR201 bounded process/session helper, PR200 migration identities. Verify direct imports and remove unused predecessor machinery. No new package, universal catalog serializer, generated provider inventory or hosted adapter.

Stop at the earliest failing required checkpoint; report partial results without weakening gates. The $0 boundary uses local compute and standard public GitHub runners, no uploaded artifacts/caches in the new workflow. RPO 24h remains an undemonstrated objective; retention remains 30 days; RTO 8h remains aspirational.

Implementation refinement: a boolean operator attestation alone is forgeable. The minimum offline approval is therefore an Ed25519 signature over the artifact digest, identity digest, target identity and independently verified channel statement, checked against a separately trusted operator key. This adds no service or package and remains separate from CMS custody. The real pinned provider generates `email_verified: true` user metadata; that exact marker (or an empty object) is recognized, with other identity metadata blocked.
